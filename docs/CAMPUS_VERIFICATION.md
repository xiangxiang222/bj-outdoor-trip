# 校园认证管理

校园身份包含在读师生和毕业校友。小程序与 H5 提供相同的状态和操作。

| 状态 | 可用操作 | 结果 |
| --- | --- | --- |
| 未申请、未通过、已撤回、已解除 | 提交认证 | 进入待审核 |
| 待审核 | 撤回申请 | 停止本次审核，保留资料以便修改重提 |
| 已认证 | 变更认证资料 | 先编辑本地草稿；提交后暂停原认证，进入重审 |
| 已认证的在读师生 | 转为校友认证 | 清空草稿中的学号和原证件，要求新的毕业证或校友证；提交重审 |
| 已认证 | 解除校园认证 | 移除认证资格、学号和当前证件关联，可重新申请 |

学校、学院等字段也被团体认证使用，解除校园认证不会一并清空这些共享字段。操作只解除当前认证关联，不承诺物理删除上传文件。服务端保留不含凭证内容的操作、版本及时间记录。

## 已有报名

- 已支付且已确认：保留原订单、成交价格和确认席位，不自动退团、退款或追缴差价。
- 待支付：支付时重新核验校园报名范围和原学生价资格；失效时返回 `409 campus_eligibility_changed`，提示重新认证或取消后重新报名，不擅自改订单价格。
- 抽签、候补：确认和递补前重新核验资格，失效者不占用新确认名额，报名记录保留以便处理。
- 自动转团：新建目标团报名时按当前身份重新核验范围，原团已支付不代表具备目标团资格。
- 已发起的团与普通活动、历史订单不会因为管理认证而自动取消。
- 报名正在支付时，先完成支付或确认支付关闭，再变更/解除认证，避免支付回调与身份变化交叉。真实微信预支付即使在本地已超时，也必须确认平台侧已关闭；当前未增加微信关单能力，未确认关闭的支付需完成付款或联系客服处理，不能仅凭本地超时放行。
- 支付阻断只关联本人付款或本人报名。公司统一支付按支付记录中的实际报名明细关联，不根据同一团期扩大到其他成员；影响预览与提交复用同一规则，已结束团期的未关闭支付也会明确列出。预览为只读，不更新支付状态。
- 新报名在 `campus_snapshot_json` 保存当时实际团费、同条件非学生价及是否使用学生优惠，不受后来价格开关变化影响。旧库未保存历史普通价，不能用当前报价反推；缺少证据且仍未处理的正团费旧单，会在学生身份变更前提示先完成、取消或联系客服核实，返回 `409 legacy_price_unknown`。已支付确认、免团费及企业统一支付报名不因缺少个人学生价记录而阻止变更。

## 接口与并发

- `GET /me/student/manage` 返回 `{ revision, status, impact: { paidConfirmed, unpaid, applied, waitlist }, paymentBlocks, priceReviews }`。计数用于说明当前行程影响；两个阻断列表独立包含历史尚未处理记录，非空时客户端说明具体原因且不允许确认提交。
- `POST /me/student/withdraw`，请求 `{ revision }`，仅允许当前待审申请。
- `POST /me/student/revoke`，请求 `{ revision }`，仅允许已认证身份。
- `POST /me/student` 提交资料时携带当前 `revision`；新版前端始终携带。首次申请且历史版本为 0 时兼容省略版本。
- 用户资料和后台用户列表返回 `studentRevision`；后台校园审核必须携带该版本，且申请仍在待审状态。
- 状态/版本过期返回 `409 student_revision_conflict`。客户端刷新后展示最新状态，不自动重复破坏性操作。
- 支付尚未处理返回 `409 campus_payment_unresolved`；旧订单缺少历史价格证据返回 `409 legacy_price_unknown`，不冒充认证版本冲突。

客户端确认页先读取实时影响，取消编辑/关闭确认不改变认证。失败保留认证和草稿，成功后同步本地用户资料。撤回会关闭对应后台待办。
