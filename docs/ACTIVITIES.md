# 同城活动

活动页采用浅紫、白色卡片和四组细线图标。默认先选兴趣，再看近期可参与活动；城区、免费、有余位放在展开筛选中，避免第一屏堆满条件。小程序保留原生选择器，H5 同时适配手机与桌面。

## 四类活动的参与信息

| 兴趣 | 发布时需要说清 | 参与边界 |
| --- | --- | --- |
| 掼蛋 | 经验要求、打法规则、费用说明；时长选填 | 不组织现金输赢 |
| 跑步 | 距离、参考配速、路线；装备选填 | 按自身状态选择，提前核对集合安排 |
| 电影 | 具体影片、影院与场次、购票方式；约定选填 | 报名活动不等于购买电影票 |
| 社团 | 社团名称、招募对象、参与内容；报名要求选填 | 本次活动报名与入会确认分开 |

社团在界面显示「社团」，沿用已有保存键「招募」，兼容历史数据。四类各有对应的标题示例、安排字段和发布入口，切换分类会保留各自填写的安排。

## 找活动与发布

- 支持兴趣、关键词、城区、今天／本周／周末、免费、有余位，以及即将开始／快成局／最新发布排序。
- 卡片直接显示时间、集合点、发起人、成局进度、余位和实际费用；最少成局人数与人数上限分别计算。
- 已开始或结束的活动退出发现列表，服务端也拦截迟到的报名请求。日期按北京时间计算；满员活动仍可查看候补信息。
- 费用初始为可见的 `0`，清空后不能提交；收费活动按正价类型提交。发布仍进入现有活动审核，审核规则不变。
- 安排字段写入既有活动介绍，不新增数据库结构。详情按字段展示，旧活动纯文本介绍继续可读。英文翻译保留字段格式，只翻译内容。
- 游客发起活动先登录，并保留选择的兴趣。请求失败提供重试；列表刷新失败保留已有内容；提交期间防止重复请求。

## 本地验证

`npm test` 覆盖发现筛选、两端一致性、四类信息往返、原生页面事件、报名生命周期与英文详情。`npm run test:ui` 使用临时数据库验证发布到详情、筛选与登录回传，并检查小屏、大字号、深色和英文布局。另检查微信 WXML／WXSS 编译及主包体积。截图中的活动为隔离测试数据。
