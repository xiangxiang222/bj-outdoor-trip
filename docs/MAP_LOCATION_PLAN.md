# 集合地点地图展示与发布选点方案

调研日期：2026-11-02。本文是待实施方案，仅新增文档，尚未接入地图服务或修改业务。

建议优先采用腾讯地图体系：小程序用微信原生选点、地图和位置打开能力，H5 与管理后台用腾讯地图组件或 JS API。先核实商业授权范围和实际报价，再确定采购。选择依据是当前产品以微信小程序为主、另有 H5 和后台，采用同一供应商更容易统一选点、坐标和展示行为；不是对各家地点准确率的实测排名。

**当前项目需要补齐的能力**

- 数据库的活动排期目前主要保存集合点文字和集合时间，没有完整地点地址、经纬度和地图来源。
- `server/src/services/policy.js` 只硬编码东直门、西直门、国贸、丽泽桥四个集合点坐标，其他地点返回高德关键词搜索外链。
- 小程序详情有坐标时调用 `wx.openLocation`，无坐标时复制地点文字；H5 详情使用地图外链，没有页面内地图预览。
- 旅游团发布主要选预设集合点，同城局主要手输文字；H5、小程序、旧发团入口和后台均需要覆盖。
- 线路预设集合点的 `geo` 字段目前是“地铁站某出口”等说明文字，不能直接当作坐标使用。
- 官方团并团依赖集合点文字和时间匹配，地点升级须兼容这一规则。

**供应商比较**

| 方案 | 与本项目有关的能力和差异 | 成本与选型判断 |
| --- | --- | --- |
| 腾讯地图 / 腾讯位置服务 | 微信原生地图组件使用腾讯体系；提供 H5 地图、搜索、输入提示、地图选点等。小程序与 H5 采用同一供应商，接入路径更直接 | 当前公开基础商业授权标价 50,000 元/年；建议技术首选，但须先确认购买范围和原生微信能力的授权边界 |
| 高德地图 | 有 Web JS 地图、地点搜索及微信小程序数据服务；使用高德的小程序服务不会把微信原生地图底图换成高德 | 当前公开基础技术服务许可标价 50,000 元/年；若已有授权、获扶持或正式报价更合适，可作为备选 |
| 百度地图 | 有 Web 地图、微信地点搜索与地址服务；百度 BD-09 坐标用于微信原生地图前须转换为 GCJ-02 | 商业用途需要付费授权，实际套餐向官方询价；若已有合作可评估，当前项目会多一层坐标适配 |
| OpenStreetMap 体系 | 开放地图数据与地图托管、搜索服务是不同层；可自建或购买相关服务，需自行组合展示、搜索和运维 | 免费数据不等于免费、无限量的生产地图服务；当前阶段不作为默认方案 |

腾讯、百度和高德都能覆盖本次地点展示与搜索需求。实际地点质量应拿北京地铁出口、商圈门口、同城活动场馆、郊区停车场和山野入口做样本验证，不能只凭地图品牌判断。海外业务若成为明确需求，再单独评估 Google Maps 等全球服务。

微信原生 `<map>` 的底图供应商不随搜索服务商切换。即使经纬度格式兼容，跨供应商展示搜索数据仍需核查数据使用条款。本期建议统一供应商；未来更换时，地图服务商的 POI 数据保存、迁移和展示也要按对应许可办理。

**第一期用户体验**

1. 发布旅游团、同城局时，集合地点区域提供“常用地点”和“地图搜索 / 选点”。已有线路的常用集合点仍可直接选择。
2. 搜索支持城市范围和关键词；选择结果后可在地图确认位置、调整标记点。郊区停车区等没有明确搜索结果的地点允许手动落点，再填写名称。
3. 选点后显示地点名称、详细地址和地图预览；另填集合说明，例如“南门右侧便利店前”“大巴停靠处”。集合时间仍是独立字段。
4. 提交发布前必须确认地图上的集合点。搜索结果不自动等同于已确认集合位置，线路目的地也不自动代替集合点。
5. 所有旅游团、同城局详情共用地点卡片：地图预览、地点名、完整地址、集合说明、“查看地图 / 去这里”。在行程和报名后的活动入口能打开同一地点。
6. 小程序用 `wx.openLocation` 打开所选坐标；H5 通过供应商支持的链接或导航入口打开位置。入口名称和提示应区分“查看目的地”和“开始导航”，以实际设备支持为准。
7. 运营后台编辑线路、发布排期和审核地点采用同样的选点能力。官方自动开团也继承完整地点数据。

一期按“每场活动一个实际集合点、线路可保存多个常用集合点”设计。若需要一辆车沿途接人，应另建多站点及时间顺序，不能在一个名称里塞多个地点。

**技术方案**

| 场景 | 建议接入方式 |
| --- | --- |
| 小程序发布选点 | 优先使用 `wx.chooseLocation`，保存返回的名称、地址与 GCJ-02 经纬度；是否满足具体搜点和微调体验通过真机验证 |
| 小程序详情展示 | 原生 `<map>` 显示集合标记，默认不展示当前用户位置；点击调用 `wx.openLocation` |
| H5 / 后台选点 | 优先验证腾讯官方地图选点组件；如确认页、样式或交互不足，再用 JS API 实现搜索、标记移动和确认 |
| H5 详情展示 | 使用同供应商地图预览，进入页面视区时再加载；保留地址文字和外部地图打开入口 |
| 自建搜索等请求 | 如需服务端 WebService 调用，通过本项目 API 封装；设置访问控制、频率限制及额度告警 |

统一保存地点结构：内部地点 ID、地点名称、完整地址、纬度、经度、坐标系、城市/行政区、数据来源、可选供应商 POI ID、集合说明、确认状态。内部统一 GCJ-02；外部数据先按官方支持的方式转换，记录原始来源。经纬度校验、字段长度限制和服务端验证一并实现。

供应商 POI ID 不是唯一业务主键：原生选点或手动落点可能没有 POI ID，不同出口也可能对应不同的实际集合位置。线路常用集合点用内部 ID 管理，发布时把地点复制成当场活动的快照；修改线路模板不应静默修改已发布活动。用户手动移动标记后，不继续把它当作未经修改的原 POI 坐标。

官方团并团需使用兼容的内部集合点标识判断，迁移期保留旧文字规则。手动标记不能简单按同名自动认定为同一点，避免把不同门口的团并在一起。现有发现页的“朝阳 / 海淀”等筛选字段与新增标准行政区字段分别适配。

**历史活动如何做到有地图**

- 优先补齐正在招募、未来出发的活动和在售线路，再处理历史记录。
- 四个预设点也要由运营确认具体门口、停车位置后回填，现有硬编码坐标不直接视为已核验。
- 只有文字的地点可批量检索候选结果，由运营确认后保存；不能把搜索第一条直接当成精确集合点。
- 未确认的旧地点保留文字并提示位置待补充，不显示误导性的精确标记。所有仍在线、可报名的活动完成确认回填后，才视为“所有在线活动支持地图展示”验收通过。
- 新建及重新发布活动要求完成地图选点；已报名活动修改集合点应明确告知参与者，并保留变更记录。

**负责人需要准备的东西**

| 准备项 | 具体内容 | 负责方式 |
| --- | --- | --- |
| 地图平台企业账号 | 建议用“同行者众”经营主体注册腾讯位置服务账号，按平台要求完成企业认证；准备营业执照、经办人及联系方式 | 负责人办理，技术协助配置 |
| 正式授权报价 | 描述小程序、H5、内部管理后台、集合点搜索、地图展示和导航跳转用途，要求确认同一主体覆盖范围、额度、超额计费及优惠 | 先取得明确回复，再采购 |
| 微信接口准入 | 小程序后台“开发 → 开发管理 → 接口设置”申请 `chooseLocation`；说明用于发布旅游团和同城活动时选择集合点，按要求提供演示材料 | 负责人开通，技术准备页面与说明 |
| 地点样本和历史清单 | 常用集合点名称、准确门口/停车位置、地图位置、到场提示；同城局挑选实际场馆，山野团挑选郊区集合点 | 运营核对 |
| 使用范围与业务规则 | 首期国内；一场一个集合点；选择后可调整；确认是否需要改地点通知、多个接人站点 | 按本文默认方案先设计 |
| 规模预估 | 每日活动详情浏览、每日发布次数、搜索次数和峰值并发的大致范围 | 负责人估算，用于报价和额度配置 |
| Key 与配置 | 按实际接入能力创建前端和服务端 Key，配置域名 / AppID / IP 等平台支持的限制；已有域名与小程序沿用 | 技术处理，服务端密钥不进前端或仓库 |
| 隐私告知 | 小程序后台隐私声明、代码接口声明、产品隐私及第三方信息清单，补充选点/定位的实际用途 | 技术按真实调用修改，负责人审阅 |

现有项目已经有小程序 AppID、域名、HTTPS 和主体信息，不需要为地图功能重新注册小程序。地理位置接口是否获准，以微信后台审核为准。

微信 `chooseLocation` 官方文档要求地理位置相关场景准入、用户位置授权及代码声明，不能只准备地图 Key。仅查看一个固定集合点的地图预览不需要读取用户当前位置；“定位到我附近”按点击触发。系统定位被拒绝时，浏览和报名继续可用，发布端提供已确认常用点或不依赖实时定位的搜点/落点备选，并清楚说明当前能否完成选点。浏览器和微信原生接口的授权行为须分别真机验证。

现有隐私文案写有“未调用定位接口”等描述，接入时须修改 `server/src/services/legal.js` 的源内容并通过现有脚本生成文档，不能仅手改生成文件。

**费用与采购判断**

正式预算按“商业授权年费 + 套餐额度之外的调用费 + 必要的并发扩容”估算，避免重复计入套餐已含额度。地图展示、地点搜索、输入提示和逆地址解析可能采用不同计量方式。

- 腾讯公开基础商业授权标价为 50,000 元/年；官网额度说明规定企业测试与正式商业使用不同。若 H5、后台使用其开放平台地图、搜索等服务，应按商业接入核定授权。实际账号、主体和项目覆盖范围以官方回复及合同为准。
- 高德公开基础技术服务许可标价为 50,000 元/年。官网“乘风计划”对符合标准的初创、小微企业提供一年基础服务，但当前写明采用定向邀请，不能当作已经取得的优惠。
- 百度协议明确区分商业用途与免费权益，本文未取得可核实的当前公开授权报价，应正式询价。
- `wx.chooseLocation` / `wx.openLocation` 方法不要求传入自己的 Key，不足以证明全部腾讯开放平台商业服务免费。只使用微信内置能力且不接入自行申请的 LBS 账号时，授权边界应向官方单独确认，不直接套用开放平台年费或承诺免费。

若完整接入费用超出预算，可另评估“小程序原生选点和展示先上，H5 暂保留地图外链”的分期范围，但须先确认原生能力的授权边界。此分期不包含完整的 H5 发布地图搜索，不能当作本需求的全量交付。

**实施与验收顺序**

1. 先用真实账号确认商业方案与微信接口权限，用代表性地点验证搜索、手动落点及 Android / iOS 体验。
2. 改造地点数据和接口、线路常用点、后台及自动开团，兼容旧数据与官方团并团规则。
3. 完成小程序、H5 的发团/同城局选点与详情地图，覆盖旧发团入口、行程入口和失败提示。
4. 回填在线活动地点，更新隐私声明，核对 Key 限制和调用监控后上线。

验收重点是“同一活动在两端展示同一实际集合位置”：搜索选点与手动落点能保存；常用点能复用；没有定位授权也能查看固定集合点；已发布快照不随模板变化；无坐标旧数据不冒充精确位置；官方团并团不因地点字段变化出现错误。自动测试集中验证坐标和快照持久化、旧数据兼容与并团规则，地图搜索质量、微信授权和实际导航通过真机验收。
