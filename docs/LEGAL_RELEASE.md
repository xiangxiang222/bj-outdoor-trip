# 协议内容、实现范围与正式发布

本轮基于携程、美团、微信官方协议与现行规范，以及仓库实际代码形成七份协议文件。更新日期和版本均为 **2026-11-01**。未部署、未连接生产数据库、未发送真实短信或发起真实支付。

## 文本与阅读入口

权威文本在 `server/src/services/legal.js`，由 `GET /api/legal` 同时供小程序、H5 使用，避免两端各维护一份不同协议。协议不使用线路 AI 翻译器自动翻译。运营主体暂采用 `docs/REGISTER.md` 记载的“同行者众（北京）体育科技有限公司”，仍须由运营方与营业执照、小程序认证主体核对。

| 文件 | 文档 ID | H5 路径 |
| --- | --- | --- |
| 隐私政策 | privacy | `/m/legal/privacy` |
| 用户服务协议 | terms | `/m/legal/terms` |
| 个人信息收集清单 | collection | `/m/legal/collection` |
| 第三方信息共享清单 | sharing | `/m/legal/sharing` |
| 设备权限与本地存储说明 | permissions | `/m/legal/permissions` |
| 敏感个人信息处理告知 | sensitive | `/m/legal/sensitive` |
| 账号注销与个人信息权利说明 | cancellation | `/m/legal/cancellation` |

中心路径为 `/m/legal`；小程序为 `/pages/legal/legal`，可用 `?doc=privacy` 等定位。我的页面、设置和登录页提供入口，未登录也能阅读。正文支持目录定位、外部来源链接、加载失败重试；阅读协议不会清掉登录表单。

在仓库根目录执行 `npm run legal:export` 可从权威文本生成 [Markdown 审阅文件](./legal/README.md)，以及两个客户端的内置只读审阅副本。它们为生成件，修改内容后须重新导出；公开部署以接口正文为准。运营联系方式仅来自 `LEGAL_*` 公开配置，不包含服务密钥。

小程序默认连接线上。当新客户端先于服务端更新，`/api/legal` 会返回 404；此时仅协议阅读页展示内置审阅副本，并明确标记尚未生效。副本总是用空发布配置从权威文本生成，不包含生产运营配置，也不能用于登录授权或保存正式接受记录。其他网络错误仍提供重试；服务端恢复后重新加载即使用服务端正文。登录确认流程不会采用副本放行，仍需部署协议接口。

## 本轮实现的协议确认

- 默认不勾选。正式发布版本在发送普通用户验证码、注册、密码登录、短信登录、微信登录和微信手机号授权前检查确认；未确认时不会先发短信或先调用微信授权。
- 后端在消耗验证码、调用第三方之前验证 `legalConsent.accepted === true` 和精确版本，拒绝缺失或过期版本。仅前端勾选不能绕过后端。
- 仅认证成功保存确认记录：用户、版本、确认范围、首次成功渠道、服务端 UTC 时间；不额外采集 IP、UA。对应正文以规范化 JSON 和 SHA-256 归档，同一版本不能覆盖正文，重复登录不重复记同版本接受记录。
- 草稿不要求接受，也不写入接受记录；客户端伪造接受草稿不会生成凭证。草稿用于本地联调和审阅，不能作为对真实个人信息处理已取得同意的依据。
- 已登录用户在付款流程调用微信账号绑定时不冒充一次新的登录同意；此路径只能绑定已有账号。导游账号短信流程沿用独立员工/服务人员流程，不假装已接受普通消费者协议。
- 版本变化返回 409，客户端清除旧勾选、刷新协议并保留表单；同版本正文冲突会阻止认证，要求运营修订版本。

**确认范围仅为用户协议及普通隐私告知确认**。不构成实名核验、公开披露、独立接收方提供、敏感信息、儿童信息或个人信息出境的单独同意。新增“敏感告知”文档也不等于已实现这些授权流程。

## 不能靠协议文案解决的真实发布问题

完整审计见 [LEGAL_DATA_AUDIT.md](./LEGAL_DATA_AUDIT.md)，来源对比见 [LEGAL_RESEARCH.md](./LEGAL_RESEARCH.md)。正式公开为可接受的协议前，运营和研发需要完成下列核对及对应实现：

1. **处理者及可用联系渠道**：核对运营主体、联系地址、隐私邮箱或电话；确认邮箱/电话可在未登录、封禁或注销后实际使用。指定请求受理人，落实十五个工作日内回复处理情况的安排，不能仅填一个无人处理的地址。
2. **第三方实际接收方**：核对微信、云基础设施、阿里认证的具体合同主体、联系方式和地区。明确独立组织者、导游等接收方身份、职责及访问范围。完成委托协议/独立提供关系判断。品牌或通用隐私政策不能代替具体产品接收方的信息。
3. **证明文件保护**：校园、校友等证明当前与公开图片共用 `/static/uploads`，可由持链接者访问。应迁移到私有存储与受控下载，校验本人/审核员权限、限制缓存和原图保留，并处理历史公开链接及缓存。不得在整改前把“仅审核员可见”写入公开承诺。
4. **敏感信息保护及最小化**：完整身份证目前直接保存在数据库字段。应按场景论证必要性、减少证件原文使用，配置匹配风险的加密、密钥和权限措施及操作审计，处理健康确认、紧急联系人、证明原件的期限和访问。界面掩码不能替代这些措施。
5. **逐场景单独同意及公开范围**：实名传输、敏感资料处理、向独立处理者提供、公开主页/行程/收藏/接龙等，分别完成合法依据判断、必要性与受众告知、独立确认及留痕。提供适当隐藏、撤回和限制渠道；目前没有主页隐私开关，不能写成已经可操作。一般登录勾选不能覆盖它们。
6. **注销与文件清理**：当前基础注销尚未同步处理校园/领队资料、内容原图、历史订单证件和紧急联系人。应落实资料分类、非必要项删除或去标识化、原始文件及备份清理、限期任务和依法保留的限制使用。交易信息三年规则不能扩张到所有资料。验证注销后仍能受理请求。
7. **AI 与跨境**：实际模型商、地区、日志和训练规则尚未核实；默认配置支持境外接口。完成接收方告知、适用出境义务、评估和单独同意之前，对真实用户需求只使用规则找团（未配 AI 密钥或将 `AI_DISCOVERY_DAILY_LIMIT=0` 可关闭找团模型调用，但这不会关闭后台起草和翻译，须分别核对）。不得只凭文本脱敏正则宣称不涉及个人信息或零出境。
8. **外部页面与未成年人**：核对 H5 自动加载的视频 iframe、地图外链和图片资源的实际第三方请求；境外播放器需另行核对。未具备儿童监护验证及专门规则之前，不开放不满十四周岁资料收集，不用通用健康确认替代监护人同意。
9. **实际履约、保险及退改**：核对组织者、资质、合同和订单展示；两端户外报名当前默认选中收费的 `outdoor` 保险，且尚无承保与出单接口。正式经营前应取消默认收费搭选，未接通真实承保前禁售/禁收保险费用，不把选项/费用当有效保单。现有出行规则、默认“不退费/风险自担”类文字及代码执行应与正式协议、有效订单和法定权利一致；新增协议不自动修复旧页面或退款流程。正式接入承保后补齐机构、合同及信息告知。
10. **存储地区、期限与证据**：核对真实部署地区，补充尚未确定的保存期限并落实清理任务。制定协议快照、普通确认及单独确认凭证的保留/限制访问规则。首次留痕机制只覆盖新认证，存量登录会话和重要政策变化需有独立的通知、重新确认及必要业务门禁方案。

这些是已在代码中发现的具体差距。将当前状态称为审阅版并不能使既有处理自动合规，也不能替代整改、合同或必要的专业审阅。要作为正式政策发布，应把正文中的“待核实”等条目改为已核实的事实，删除不适用项目，并再次验证实际网络请求、权限和数据生命周期。

## 正式发布配置与版本规则

默认 `draft`，`effectiveAt` 为 `null`。只有下列条件同时满足才显示为 `published`：

```dotenv
LEGAL_OPERATOR_NAME=与执照和实际运营一致的主体全称
LEGAL_OPERATOR_ADDRESS=可接收联系的真实地址
LEGAL_PRIVACY_EMAIL=实际有人处理的邮箱
# 邮箱与电话至少一项有效；另一项可选，不得填虚构值。
LEGAL_PRIVACY_PHONE=实际联系电话
LEGAL_EFFECTIVE_DATE=2026-11-01
LEGAL_REVIEWED_VERSION=2026-11-01
LEGAL_PUBLISHED=1
```

生效日须为真实日期、不早于正文更新日且不晚于北京时间当前日期；未来生效日仍按草稿显示，因此提前公告时不要把该显示机制当作正式过渡期方案。`LEGAL_REVIEWED_VERSION` 是运营对本版核对已完成的显式配置，程序本身无法证明前述整改已经完成。**不要直接复制示例值开启正式状态。**

修改正文、运营主体、联系方式或生效信息会改变正文快照；已经有确认记录后，须更新 `VERSION`、`updatedAt` 和对应发布配置，保留旧版凭证，并重新导出审阅文件。后端拒绝用同一版本覆盖已归档正文，不应通过删历史记录来规避版本冲突。

本轮仅修改工作区并进行本地验证。没有部署或开启正式协议状态。
