# 一句话找团 · 首期实现

首页搜索下方的「说说你想怎么玩」进入新页。小程序为 `pages/discover/discover`，H5 为 `/m/discover`。普通筛选和日期选择继续保留。

## 用户可以完成什么

1. 描述时间、目的地、人均团费上限、人数、轻松偏好、团型或跨校偏好。例如「下周末去怀柔，团费200元内，轻松一点」。
2. 检查理解出的条件；可以修改、清空单项，或按这些条件继续查看更多。
3. 比较 2–3 个真实团期的集合、费用、报名范围等资料，再进入已有详情和报名流程。缺失信息标为未提供，不由模型补全。

预算为**每人团费**，0 表示免费；报价按当前账号下一位报名的价格核算，以报名页最终核算为准。同行人数用于余位提醒，不会自动代多人报名，也不承诺所有人价格相同。跨校依据团期实际报名范围，登录、校园或团体认证要求仍由现有服务端规则核验。

这版只查询山野出行团。全包总价、任选多个日期、指定学校/学院/专业、特殊人群适应性、活动等未覆盖的硬要求，会请用户确认或转到现有入口，不自动删掉条件后推荐。明确的筛选无匹配时保留条件，可以由用户主动清除。

## 模型和真实业务的边界

- `POST /api/discovery/search` 为只读接口。模型只辅助整理条件，不决定团期 ID、价格、名额、资格或支付。
- 真实结果只取公开、已审、已上架、未开始的招募/成团排期。邀请码团不参与推荐。模型等待结束后重新读取业务状态。
- 使用现有报价、真人报名计数、锁座和校园/组合团资格核验。虚拟热度不充当真人报名，不把线路标注里程认定为步行距离。
- 只向模型发送公开目的地词与脱敏后的用户描述；手机号、身份证号、邮箱会遮蔽。账号、订单、支付资料不会作为模型上下文。
- 未配置密钥、超时、限额或非法输出时回退规则匹配，返回 `mode: rules`。实际成功采用模型条件时返回 `mode: model`。页面如实表达整理方式。

## 配置

复用服务端 `AI_API_KEY`（或 `OPENAI_API_KEY`）、`AI_BASE_URL`、`AI_MODEL`，使用现有兼容 `chat/completions` 的 JSON 协议。仅放在服务器 `server/.env`，客户端不持有密钥。

| 配置 | 默认 | 用途 |
| --- | --- | --- |
| `AI_DISCOVERY_TIMEOUT_MS` | 7500 | 模型超时；最高 7800 ms，随后回退 |
| `AI_DISCOVERY_CONCURRENCY` | 3 | 同时调用模型数 |
| `AI_DISCOVERY_DAILY_LIMIT` | 200 | 北京时间日调用次数；0 关闭模型调用 |
| `AI_DISCOVERY_PER_MINUTE` | 20 | 每 IP 每分钟搜索数 |
| `AI_DISCOVERY_GLOBAL_PER_MINUTE` | 120 | 服务进程每分钟搜索数 |

配额按进程内存计数，重启会重置；多进程部署需共享计数后再放大量。规则查询不消耗模型配额，但仍受搜索限流。没有配置模型时功能仍可使用，不需要在本地或生产重新初始化数据库。

## 验证与后续验收

- `server/test/discovery.test.js`：真实接口、数据边界、当前报价、真实余位、校园及组合团资格、日期、无副作用、输入校验、限流，以及模型异常/超时/隐私。
- `server/test/discovery-eval.test.js`：固定北京时间的 100 条中文输入评估；只代表这些用例，不代表开放输入的准确率。
- `server/test/miniprogram-discovery.test.js` 与 `web/src/utils/discoveryState.test.js`：零预算、编辑、分页、重试、比较、过期响应等。
- `scripts/ui-discovery-cases.cjs`：使用临时数据库，在实际浏览器验证入口、搜索、修改、对比、详情、空结果、重试及窄屏/大字/暗色/英文/桌面。运行前先构建 H5。
- 原生页通过 WCC/WCSC 编译与源码包大小检查；最终上传体积和真机输入/日期控件仍以微信开发者工具验收为准。

本地未配置真实模型密钥。外部模型的连通性、效果、费用需在服务器配置后验收；协议使用本地 HTTP 模拟服务验证。当前工作只实现与验证本地代码，未部署。
