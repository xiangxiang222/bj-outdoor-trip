# 意思意思 · 首版产品说明与验收

范围：日常心愿认领 + 已有真实行程订单。没有合作商家时，不提供奶茶、餐饮、景点、演出、车票的线上购买或出票；不开放自由收款、资金目标、资金池、余额转账或提现。该功能的命名和金额大小不能代替真实业务、支付渠道准入与平台审核。

## 使用路径

- 活动页 / 我的 → 意思意思 → 选一份小美好 → 写下心愿 → 分享给熟悉的朋友。
- 日常心愿不填写金额。朋友可认领安排、归还认领或留一句祝福；由认领人标记「已安排」，表示朋友之间的记录，不代表商家确认交付。
- 旅行心愿可不关联订单，只做免费认领；也可关联本人已经报名、可支付的真实行程。关联后的收礼人为订单中的脱敏出行人，不可自填替换。
- 关联订单的心愿不再认领安排，朋友通过现有团费支付页代付或分摊。金额、付款记录及退款沿用原报名账本，不增加席位。付清团费不会把心愿标记成已履约。
- 关闭仅关闭心愿内的认领、祝福与付款入口。原报名、已有付款链接、已付款记录和订单退款规则不受影响，关闭不会退款。
- 每笔报名仅可关联一份心愿（关闭后也不重新绑定）；订单详情可回到已经关联的心愿。
- 没有公开心愿广场；通过随机链接分享。原订单电话号码、证件号、报名 ID 和支付分享 token 不出现在公开心愿详情。用户自己输入的称呼、标题、说明、祝福及公开昵称会出现在分享页，创建时明确提示不要填写敏感信息。

## 状态与并发

| 场景 | 可执行操作 | 结果 |
| --- | --- | --- |
| 免费、未认领、未关闭 | 非发起人认领；登录者留祝福 | 独占一位认领人；每人每份一条祝福 |
| 免费、已认领 | 认领人归还 / 标记已安排 | 归还恢复可认领；已安排停止认领与留言 |
| 真实订单、未付清且可支付 | 登录后打开原订单支付页 | 仅抵扣该笔报名团费 |
| 付清、取消、退款、出发或结束 | 查看现有记录 | 心愿不继续提供付款入口 |
| 关闭 | 查看记录 | 不取消原报名，不触发退款 |
| 认领人注销 | 自动释放尚未完成的认领 | 版本递增，其他朋友可重新认领 |
| 发起人注销 | 分享详情不再可访问 | 不自动改动已有付款账本 |

创建与祝福使用幂等键，响应丢失重试不重复写入；状态操作必须带 revision，过期版本返回 409，前端刷新但不自动重放意图。每个账户每天最多新建 20 份心愿；个人记录使用 cursor 分页，默认每页 30，最多 50。公开祝福返回最近 100 条，已祝福资格独立查询。

认领、归还、标记安排、关闭和收到祝福接入站内消息。未新增短信或商家消息发送承诺。

## 接口

新增 `wishes`、`wish_participants`、`wish_blessings` 三张表及唯一索引，应用启动通过既有 schema 创建机制自动补表，保留业务数据，无需运行 seed。

| 方法 | 路径 | 身份 / 用途 |
| --- | --- | --- |
| GET | /api/wishes/meta | 公开类别配置 |
| GET | /api/me/wishes?tab=created\|joined&cursor=… | 当前用户心意簿 |
| GET | /api/me/wish-orders | 本人可关联订单，排除已有心愿的报名 |
| POST | /api/wishes | 创建，`idempotencyKey, kind, title, recipientName?, note?, enrollmentId?` |
| GET | /api/wishes/:token | 分享详情；登录时附当前身份权限 |
| POST / DELETE | /api/wishes/:token/claim | 认领 / 归还，`revision` |
| POST | /api/wishes/:token/complete | 认领人标记安排，`revision` |
| POST | /api/wishes/:token/close | 发起人关闭，`revision` |
| POST | /api/wishes/:token/bless | `message, idempotencyKey` |
| GET | /api/wishes/:token/payment | 登录后再次核验原订单，返回已有支付分享 token 与 `mode: split` |

公开 token 由 24 字节随机数产生。标题 40 字、称呼 20 字、说明 240 字、祝福 80 字，服务端校验类型和 Unicode 字数，新增用户文本接入既有微信内容检测。仅旅行类别可绑定本人订单；支付资格同时检查席位、实付余额、审核、取消、北京时间出发日期、开始 / 完成标记和校园资格。没有新增支付写入接口。

## 自动验收与实际联调边界

- `server/test/api.wishes.test.js`：鉴权、越权、真实订单资格、并发认领、版本冲突、幂等、隐私、分页、注销、原付款人退款和关闭边界。
- `server/test/miniprogram-wishes.test.js`：原生控制器的重试、竞态、账户切换、分页、认领、支付跳转与入口复用。
- `web/src/views/mobile/Wishes.test.js`、`OrderDetail.test.js`：H5 表单、真实支付跳转、冲突、幂等、身份切换和已有心愿入口。
- `scripts/ui-wishes-cases.cjs`：真实浏览器创建、朋友认领 / 祝福 / 完成、原订单钱包分摊、关闭保留订单、访客登录回跳、加载失败恢复、窄屏 / 桌面 / 深色 / 大字 / 英文。
- 微信 WXML/WXSS 编译与小程序包体检查不代表真机测试；微信转发、真实微信支付与真实退款仍需在已配置支付商户的体验版进行联调。自动测试用隔离数据库，不扣真实资金。

当前没有合作商家，因此日常品类保持免费认领安排。未来接入商家需另做真实商品、库存、履约、客服和售后闭环，并确认支付及平台准入，不能直接把免费心愿改为自由收款。
