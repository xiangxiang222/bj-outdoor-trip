# 生产集成与验收边界

本轮验证在隔离的临时数据库中完成，没有访问生产服务器、执行部署或发起真实付款、退款和短信请求。

## 登录与签名

- 生产进程须设置 `NODE_ENV=production`。
- `JWT_SECRET` 必须显式配置为至少 32 字符的随机秘密，不能使用仓库中的开发默认值或明显重复的字符序列。缺失或过弱时应用会在启动前拒绝加载配置。更换该值会使已有登录凭证失效，需要重新登录。
- 小程序微信登录需要正确的 `WX_APPID`、`WX_APPSECRET`。生产环境未接通时，微信登录接口返回 503，不创建模拟身份，也不通过请求中的手机号绑定账号。
- 验证码短信需要 `TENCENT_SECRET_ID`、`TENCENT_SECRET_KEY`、`TENCENT_SMS_SDK_APP_ID`、`TENCENT_SMS_SIGN`、`TENCENT_SMS_TEMPLATE_ID`，以及相应账号权限、审核通过的签名与模板。生产环境缺少配置时无法发送或消费演示验证码；`/api/meta` 不会返回 `888888`。

## 微信收款、退款与提现

- 真实收款需设置 `WX_PAY_MOCK=0`，并配置有效的 `WX_APPID`、`WX_MCH_ID`、`WX_MCH_KEY` 和 `WX_PAY_NOTIFY`。微信登录、商户与小程序之间的绑定关系也需要在对应平台确认。
- 原路退款需要可用的商户证书：`WX_MCH_CERT_PATH`、`WX_MCH_KEY_PATH`，以及配置使用的 `WX_MCH_CERT_PASS`。提现到微信零钱另需商家转账权限、证书、有效的 `WX_TRANSFER_SCENE_ID`，并遵守商户平台实际开通的场景规则。
- 生产环境未配置真实支付时，团费、会员购买、余额充值、企业统付、微信提现和微信退款均会失败，不会用模拟成功结果生成账款。`/api/pay/mock-success` 在生产环境不可用。
- 已有余额支付和退回余额属于实际内部账务，仍可使用。退款接口拒绝时不会提前收回活动奖励积分。
- 以上检查能识别缺失配置和演示模式，不能代替商户权限、证书有效期、回调可达性及对账验收。

## 业务通知短信

`sendSms()` 当前只记录解散、候补、优惠券等业务通知，没有向腾讯云提交短信请求。有效号码的日志状态为 `recorded`，无效号码为 `skipped`；日志条目不会被统计为已发送。解散结果中的 `smsCount` 因此为 0，`smsRecordCount` 表示写入的待发送通知条数。未接入真实微信订阅通知时，微信通知日志同样标为 `recorded`，不会伪装成 `sent`。验证码短信使用独立的真实发送实现，配置验证码模板不等于业务通知已经接通。

业务通知上线还需要分别申请与内容相符的模板、配置模板参数映射、实现真实发送及失败处理，再将供应商确认接受的记录标为 `sent`。本轮没有替运营选择模板或发送通知。

## 仍需授权环境和真机验收

1. 微信开发者后台确认 request、uploadFile、downloadFile 合法域名及 AppID，体验版在 iOS、Android 真机验证登录、手机号授权和分享。
2. 使用实际开通的微信商户能力验证小额收款、取消支付、异步回调、重复回调、订单查询、原路退款、余额退款和提现确认，并核对微信账单与应用账本。
3. 在真实手机号上验证验证码短信的成功、供应商失败、频控和错误验证码；业务通知接通后单独验证通知模板及发送结果。
4. 在目标服务器确认上述配置和证书存在且权限正确，再通过现有 GitHub Actions 流程上线。本轮未检查或更改服务器环境变量。
