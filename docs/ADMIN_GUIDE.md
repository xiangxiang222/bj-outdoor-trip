# 同行者众 · 管理后台使用文档

后台与用户端共用同一套 API。本地默认地址：

- 后台：[http://127.0.0.1:3781/admin](http://127.0.0.1:3781/admin)
- 若已执行 `npm run build` 并由 API 托管静态资源，也可访问 [http://127.0.0.1:3780/admin](http://127.0.0.1:3780/admin)
- 线上：[http://192.144.167.212/admin](http://192.144.167.212/admin)

## 1. 登录

1. 打开 `/admin`，未登录会跳到 `/admin/login`。登录页顶部一条红栏，下面是白卡片，小标旁写「同行者众 / 管理后台」
2. 默认账号：**admin** / **admin123**（由 `npm run seed` 写入；角色为管理员）
3. 登录成功后 token 存在浏览器 `localStorage.bj_admin_token`，并记下姓名与角色
4. 右上角账号菜单「退出登录」会清除 token 并回到登录页
5. 顶栏左侧是小标和「同行者众」。右侧「用户端」「导游端」在新窗口打开前台和带团工作台。有运营权限时还有「消息」。账号菜单里同样可打开两端，并用于退出登录

角色：

- **超级管理员**：全部权限，含管理其他后台账号
- **运营**：线路、拼团、报名、用户会员；不能增删改其他管理员
- **领队**：看出团与名单，改车辆座位；不能动财务、用户和账号
- **摄影**：看出团与名单、上传照片；不能改座位和财务

密码错误会在页面提示「账号或密码错误」。停用账号无法登录。上线后请立即在「管理员」页修改种子密码并更换 `JWT_SECRET`。

## 2. 左侧菜单

侧栏按经营 / 用户 / 设置分组，固定在窗口左侧；右侧内容单独滚动。宽表左右滑动时，拼团表的「线路」「出发」钉在左侧，方便对照操作；操作列不钉死。滑到最右应能完整看到最后一列按钮。


| 菜单 | 路径 | 用途 |
| --- | --- | --- |
| 数据看板 | `/admin` | 线路数、用户数、报名人数、已收金额、公司挂账人数；各线路人数/收入柱线；按天数饼图 |
| 线路管理 | `/admin/routes` | 新增、编辑、下架线路；上传封面与相册；可贴 B 站等视频链接 |
| 拼团与成本 | `/admin/schedules` | 发布排期、审核用户发团、填成本、看利润、本团画像、虚拟报名、公司结算、解散；含同城局 |
| 报名与收款 | `/admin/enrollments` | 报名明细、筛选、代取消报名 |
| 优惠券 | `/admin/coupons` | 按团发行公开/会员/定向/免费券、指定必领、搜索分页选人、暂停领取、台账、复制短链/二维码 |
| 抽奖 | `/admin/lottery` | 按团配置转盘、时机、指定中奖；「查看」看奖品详情和中奖人；拼团列表「抽奖」会跳到这里 |
| 用户与会员 | `/admin/users` | 搜索用户、开通/取消会员、调整积分、注销账号；顶部可预生成虚拟用户池 |
| 认证审批 | `/admin/verify` | 校园、团体、领队待审。消息点进来会高亮对应申请，可直接通过或拒绝 |
| 玩法标签 | `/admin/tags` | 首页「想怎么玩」标签：名称、颜色、配图 |
| 退费规则 | `/admin/refund` | 全局取消退费比例。默认所有线路使用；某一条线可在线路编辑里单独改 |
| 管理员 | `/admin/staff` | 仅管理员可见：增删改后台账号、停用、重置密码 |
| 用户端（顶栏） | 新窗口 `/m` | 核对前台展示 |
| 导游端（顶栏） | 新窗口 `/g` | 核对带团工作台 |


## 3. 数据看板

打开后自动请求 `GET /api/admin/dashboard`。

- **已收金额**：仅统计 `pay_status=paid` 的报名 `pay_amount`
- **公司挂账待结算**：`company_pending` 人数，提醒运营去「排期与成本」点结算
- 表格按线路汇总人数与收入，便于发现热门线
- 已取消的报名不计入人数

刷新页面即可拉取最新数据（无自动轮询）。

## 4. 线路管理

### 4.1 列表

展示封面缩略图、编号、标题、天数、类型、地区、成团人数、状态（`on` / `off`）。用户端列表只展示 `on`。

### 4.2 新增

点「新增线路」，按区块填表，**不用写 JSON**。新开对话框默认是 **AI 起草**，编辑已有线路默认是 **手动**。至少填写标题，并保留至少一档人数价、一种车型。

- **手动**：自己填下面各栏
- **AI 起草**：先填标题、地区、天数、类型和补充，点「生成文案和图片」。有 `AI_API_KEY`（或 `OPENAI_API_KEY`）时走兼容 OpenAI 的聊天接口写文案；没配密钥用模板。图片先对已有景点库，再搜百度，百度没有再试 360。生成后仍可改。没搜到图会提示自己上传。
- 天数：1 / 2 / 3 / 多日（存 5）
- 地区：一个级联框。全国省 / 市 / 县，可只选到省或市；「北京周边」「跨省」在选项最上面。存成 `北京市 / 怀柔区`
- 类型、难度、季节；首页「想怎么玩」标签在「玩法标签」菜单维护，这里的「标签」是线路自己的 chips
- 成团人数、介绍、**视频链接**（B 站完整分享地址、YouTube、mp4；线路页嵌播放器）、亮点、行程、费用含/不含、装备、注意事项
- **退费规则**：默认「使用全局规则」（设置 → 退费规则）。关掉后为本线路单独设档位，例如 10 天前 100%、3 天前 80%、不足 3 天 50%。须保留提前 0 天一档覆盖出发当天未开团。正式开团后一律不退。
- **阶梯价**：按「几人起 / 单价 / 会员价」加档。改单价默认按 95 折填会员价，也可手改。可点「填四档模板」（10/20/30/50 人）
- **可选车型**：勾选后，发团只能从这里选
- **集合点**：手填或从东直门 / 西直门 / 国贸 / 丽泽常用点加入

保存调用 `POST /api/admin/routes`。未填 `code` 时服务端会生成 `R{时间戳}`。起草调用 `POST /api/admin/routes/draft`。

### 4.3 封面与相册

封面、相册通过 `POST /api/admin/upload` 上传，支持 jpg / png / webp / gif，单张不超过 5MB。上传后得到 `/static/uploads/...` 相对路径并写入线路。点预览图可更换，相册可多张、可移除。

种子线路封面仍可能在 `server/public/static/photos` 与 `static/routes/*.svg`。

### 4.4 编辑

「编辑」回填当前行，仍是同一套表单。保存时 `PUT /api/admin/routes/:id`。阶梯价和车型会整表替换，界面上看到的档位和勾选即最终结果。

### 4.5 下架

「下架」调用删除接口，**不会物理删除**，只把 `status` 改为 `off`。已有排期与报名仍保留，用户端不再展示该线路。

## 5. 排期、成本与解散

侧栏文案为「拼团与成本」。用户从首页「发团」或活动 Tab「发起一局」提交的团会显示「待审」，通过后才出现在用户端（山野团上首页，同城局上活动 Tab）。玩法标签在侧栏「玩法标签」维护。同城局排期 `channel=activity`，不要按大巴团去填车牌座位，除非确实需要人数上限。

### 5.1 发布排期

「发布排期」选择线路、出发日、个人/公司/高校、车型、成团人数、集合点。

- 车型决定 **座位上限**（10 人考斯特 / 30 人中巴等）
- 结束日 = 出发日 + 线路天数 − 1
- 后台开团 `organizer_id=0`，组织者显示为管理员姓名
- 公司类型须填公司名；高校类型须填学校名，付款同个人拼团，会出现在用户端「高校」
- 可选「虚拟报名」人数：从虚拟用户池抽人占座；池不够会自动补人。名单为常见中文姓名、籍贯、手机和紧急联系人
- 可勾选「仅师生」、允许校友、报超会抽，或填写限定高校（逗号分隔）。填了高校后只有认证学校匹配的人能报；允许校友后，已认证校友也可报。列表「限制」可事后改
- **高校免费团**（类型选高校 + 团型免费）：发布时默认打开报超会抽、仅师生，并用学校名作为限定高校。先报名待确认，超过座位才抽签决定出行人；列表「确认出行名单」操作与普通报超会抽相同
- **报超会抽**：对外文案是「如果报名多了，会抽」，不要写「抽名额」。名单未确认前报名是 `applied`。点「确认出行名单」：未超座位则全部确认，超过则抽签。重复确认会被拒绝

### 5.2 虚拟报名

先到「用户与会员」顶部生成一批虚拟用户，各团从这批人里抽。线路发布后也可在该行程行点「虚拟」，随时把本团虚拟报名人数改成需要的值（增加则从池里补人，减少则取消占座、人回池）。人数上限为剩余座位（不含已锁定座位）。真人报名需要座位时，会取消一名虚拟用户腾座。前台排期接口不返回 `virtualEnrolled`，名单与真实报名一样脱敏展示。

后台用户列表把这类账号标成「虚拟」。线路管理或拼团列表点「评价」，可用虚拟用户给线路写评价。

### 5.3 填写成本与利润

点「成本」，分别录入：大巴、门票、住宿、餐食、导游、其他（单位：元）。保存后列表立刻显示：

- **收入**：该团已支付报名的 `pay_amount` 之和（个人已付 + 公司已结算）
- **成本**：六项之和
- **利润**：收入 − 成本

未结算的公司团收入为 0，利润会显示为负成本，属正常现象。

### 5.4 本团画像

点「画像」拉取该排期报名的性别饼图、年龄段饼图、籍贯柱状图。数据来自报名时的身份证解析。证件格式错误时可能落入「未填」或仅用手动字段。

### 5.5 公司结算

点「公司结算」会把该团所有 `company_pending` 改为 `paid`，金额按**当前人数对应的阶梯原价**（非会员价）计入。个人拼团无需此操作。

列表「导游」列点姓名可查看简介、擅长线路与近期带团。未成团显示「未匹配」。

有现场权限（管理员 / 运营 / 领队）可点「开团签到」：标记正式开团；随时发起出发前上车或行程休息点签到；核对名单后点「确认本轮签到」，然后才能开下一轮。未上车、没有签到记录的交费客，行程结束后仍可抽奖。

### 5.6 本团抽奖

左侧「抽奖」或拼团列表「抽奖」进入。发团时可设时机：不开、报名前、报名后、前后都抽。配置页可再改时机、圆盘（2～8 个奖品）、权重（相对中奖率）、库存、转动秒数（默认 5）。也可指定某用户抽中某档奖，用户端转盘动画与别人相同，看不出被指定。保存奖品后可关页；列表「查看」看奖品详情（类型、中奖率、库存、已中人次）和中奖人（手机、是否会员、报名、领取、指定）。报名前抽的人可能还没报名。中奖后立刻提示奖品和这档中奖率，积分/实物跟团结束后才能领。未配置或未启用时，前台用平台默认积分/水/券奖池（报名前一次，交过费且行程结束后再抽一次，不必签到，中奖立刻入账）。这与「报超会抽」确认出行名单不是一回事。

### 5.7 优惠券

个人拼团可点「优惠券」或打开「优惠券」菜单。发行时选指定行程或「全部团（通用券）」、发给谁（公开领取 / 仅会员 / 定向发放）、几折（须填最高减免）、立减或免费、张数。公开、会员都可以指定必领人：点「从名单选」，按昵称、手机或**高校名单**搜，或翻页勾选（只看会员、只看已认证师生可筛）。也可直接选一所学校并勾选「发给该校全部已认证师生」。指定的人发行后立刻入账，库存先留给他们；公开券其余人仍可领剩下的，会员券其余会员领剩下的。可填领取后有效小时、近几个月未参加、出行次数门槛；勾选后可与会员价或学生价叠加，默认仍取更低不叠加。点「预览符合人数」看覆盖。**定向发放**发行弹窗只留选人和优惠规则：选中的人立刻入账，张数按已选人数；人多可在名单里按学校筛选或全选该校。高校名单、久未参加、出行次数、预览、按条件发放都放到「发放」里，避免和选人重复。定向也可先不定人、只定量，之后到「发放」里按名单/高校/手机/全部会员或条件补发。公开券生成短链 `/c/口令` 与二维码。补发：点「发放」，同样从名单/高校筛选选人、填已注册手机、全部会员，或再按条件发放。可写演示短信（每人每天最多 1 条券短信，链接为一券一码）。暂停后不能再领，已领未用仍可报名核销。台账看谁领了、是否已用、何时过期。公司团不能发券、不能用券。免费券团费为 0，保险另计。

### 5.8 解散拼团

- 单团：列表行「解散」，填写理由（必填，不超过 200 字）
- 全部：页顶「解散全部拼团」，会解散当前所有进行中的团（含用户开的团）

解散后：

1. 排期 `status=cancelled`，写入解散理由与操作人
2. 有效报名全部取消；已付款的 `pay_status=refunded` 并记一笔退款支付单
3. 向出行人写入取消短信日志（`sms_logs`，场景 `cancel`）
4. 已解散的团不能再报名、不能再结算
5. 列表默认不展示已解散的团（报名、退款记录仍保留）。需要核对时勾选「显示已解散」

解散全部请谨慎使用。线上走查脚本默认**不会**调用该接口。不提供物理删除。

## 6. 报名与收款

明细：线路、日期、姓名、手机、紧急联系人、性别、籍贯、支付状态、报名状态、金额。身份证字段已掩码。可用姓名/手机/线路关键词、支付状态、报名状态筛选。

有效报名可点「取消」：释放名额，已付款标记退款（演示态，非微信原路退款）。已解散的团里的报名一般已是取消状态。

支付状态含义：

| 值 | 含义 |
| --- | --- |
| `unpaid` | 个人拼团已占座，费用待出行前支付 |
| `paid` | 已支付（个人付款或公司已结算） |
| `company_pending` | 公司团挂账 |
| `refunded` | 已退款（用户取消、后台取消或拼团解散） |

报名状态：`joined` 已确认出行 / `applied` 已报名待确认 / `waitlist` 候补 / `cancelled` 已取消。同城局报名通常没有身份证，紧急联系人列为空属正常。

也可请求 `GET /api/admin/enrollments?scheduleId=&q=&payStatus=&status=`。

用户提交校园、团体或领队认证后，后台右上角「消息」会出现待办，红点为未读数。点一条会跳到 `/admin/verify?kind=campus&userId=`（或 `kind=group` / `kind=leader`），高亮该申请。通过或拒绝后对应消息自动已读。约 20 秒刷新一次。侧栏「认证审批」也可直接打开。领队通过后，个人账号角色变为领队，可在团详情页报名领队位。

## 7. 用户与会员

列表不含已注销账号。可按手机、昵称、公司名搜索。表格含学生、团体、领队列。认证待审请到「认证审批」。

- **过校园 / 过团体 / 过领队**：也可在本页点按钮，调用 `POST /admin/users/:id/verify`。通过后学生可走 9 折，并可报「仅学生」或指定高校的团。校友通过后不享受学生价。领队通过后可在团详情报名领队
- **开通 / 续费**：与用户端相同，顺延 365 天并赠送开通积分
- **取消会员**：清空会员标记与到期日，积分保留
- **积分**：正负整数，需填写原因；不能扣到负数
- **注销**：与用户自行注销相同（取消未出行报名，清空手机等，同一手机可再注册）
- **虚拟用户池**：页顶可一次生成若干虚拟用户。各团「虚拟」报名从空闲的人里抽；不够时自动补进池

## 8. 管理员

仅角色为「管理员」的账号能打开此页。

- 新增：账号（字母开头，3–32 位）、姓名、角色、初始密码（≥6 位）
- 编辑姓名与角色；重置他人密码无需原密码
- 停用后无法登录；已签发 token 访问后台会 401
- 不能删除或停用当前登录账号；不能去掉最后一名启用中的管理员
- 「修改我的密码」需验证原密码

## 9. 日常操作建议

1. 先在「线路管理」确认上架线路、阶梯价与封面；在「玩法标签」维护首页 chips
2. 在「拼团与成本」发布近期班期，或审核用户发的山野团 / 同城局，通过后补成本
3. 在「认证审批」处理校园、团体、领队待审
4. 关注看板「公司挂账」，定期结算
5. 活动结束后补全成本，核对利润
6. 不要在生产库执行 `npm run seed`（会清空业务数据）
7. 解散拼团前确认理由，解散全部仅用于清场或演示重置

## 10. 故障排查

| 现象 | 处理 |
| --- | --- |
| 登录后立刻回登录页 | 确认 API 已启动；浏览器是否禁用 localStorage；token 是否过期（默认 7 天）；账号是否被停用 |
| 看板全 0 | 未 seed 或连错数据库；确认 `server/data/app.sqlite` |
