# 三端界面与发团流程

## 视觉语言

依据项目内的 `app.json`、Vue Router、API 路由与 `docs/CODEMAP.md`，同一套旅行服务仍由 Express API 和 SQLite 提供。小程序、手机 H5、桌面网页、导游工作台与管理后台共用「同行者众」品牌；消费端以克制的紫色、淡薰衣草、白色内容区和实景山野照片组织界面。桌面 H5 使用宽屏导航、内容栅格与可扫描的信息带；窄屏继续使用四个高频入口，不把手机页面放大冒充桌面设计。

## 出行者流程

首页以真实目的地影像开始，搜索线路与团期，选定日期、浏览目的地灵感，然后进入线路 / 团详情。首页明确区分「高校同行」与「公司团建」入口；线路详情的发团入口沿用相同的组织身份与线路预选。报名与退费仍走现有 `/schedules`、`/enroll`、`/pay` API，消费端没有旁路业务接口。

发布山野团分为线路、组织与招募范围、出行安排、确认四步。个人、高校、企业三种组织方式仍映射到既有 API 字段；高校的「本校」「跨院」「跨校」以学校 → 学院 → 专业绑定组合进行配置，未选学院不会被推断成全校开放。预览按目标组合显示报名范围。日期、可用车型、座位人数、最少成团数、口令和活动收费会先校验；确认页按团型显示免费状态或会员、学生价格，并列出发起身份。发布结果按真实接口进入对应状态：用户发团待审批，同城局待管理审核，已有线路排期按现有 `/schedules` 流程处理。

学生认证仍采用学校 → 学院 → 专业顺序，并保留学号、证件上传及后台审核。会员等级按成长值展示权益和进度；高校价仍由服务器资格校验，页面不会仅凭表单选择授予价格。

## 导游与管理

导游端以待服务、今日和历史行程划分工作，显示集合、车辆、名单与逐轮签到进度；名单可按姓名、座位或电话尾号检索，确认动作沿用现有权限与行程 API。管理后台以运营导航、待办、经营指标和业务表格重新组织线路、发团审批、报名、用户与团体认证等操作。管理员权限、API 鉴权、经济操作与审批规则仍由服务端决定。

## 验证

- H5：`npm run build --prefix web`、`npm run test --prefix web`。
- 小程序：微信开发者工具编译器检查 WXML / WXSS、页面事件及本地图片路径。
- 发团：检查报名范围、跨校组合、重复提交、车型人数、收费与组织身份。
- 视觉走查：浏览器验证 390 × 844 手机和 1440 × 1050 桌面，以及会员、校园发团、管理员与导游工作台。
- 本地页面预览使用独立 `/tmp` 演示数据库，不重置 `server/data/app.sqlite`。
