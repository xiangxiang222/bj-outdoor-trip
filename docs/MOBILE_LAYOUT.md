# 用户端底部导航、同城局与品牌顶栏

对照微信小程序设计指南、常见旅行/同城产品，以及仓库里现有 H5 / 小程序实现。底栏为 **首页 / 活动 / 行程 / 我的**。「官方」是「我的」里的客服页，活动页是同城局列表，行程是待出行与历史报名。

下列 1–6 节是已落地的第一轮改版说明；第 7 节是同城局轻报名；第 8 节是图形标与夜色顶栏。

## 1. 当时的问题（已改）

当时底栏是 **首页 / 活动 / 官方 / 我的**。

| 问题 | 为什么别扭 |
| --- | --- |
| 「官方」占了 1/4 底栏 | 微信建议 Tab **不超过 4 项**，且只放**高频去处**。账号、规则、FAQ 是低频查阅，马蜂窝、携程、活动行都把客服放进「我的」。 |
| 「活动」和户外团抢词 | 绿野、8264、俱乐部小程序里「活动」= 这次出行。本产品却拿它装掼蛋 / 跑步 / 电影，用户点进去会以为能报山野团。 |
| 活动页套用线路大图卡 | 同城局关心的是**周几、几点、在哪、还缺几人**。风景封面 + 会员价三列是首页的语言，不是局的语言。 |
| 活动页经常是空的 | 早期种子只有户外排期。空态只有一句「还没有活动」，没有分类入口，也没有发起理由。 |
| 官方页是通讯录 + 长文 | 平台号、微信号、规则章节、FAQ 平铺成十多张卡，没有主操作。微信指南要求**一页一个重点**。 |
| 文档曾和实现不一致 | 旧版 `USER_GUIDE` 写「首页 / 官方 / 规则 / 我的」，规则页其实已重定向到官方。 |

## 2. 调研摘要

**微信《小程序设计指南》**

- 标签栏 2～5 项，**建议不超过 4 项**，保证点击热区。
- 一页一组标签；导航只回答「现在在哪、还能去哪」。
- 每页一个重点；规则、说明放到决策之后，不要和主任务抢位置。
- 客服用 `button open-type="contact"`（真机），H5 演示用复制微信号代替。

**旅行 / 出行**

- 携程 / 飞猪：首页（订）+ **行程/订单** + 我的。客服不进 Tab。
- 马蜂窝改版：把个人中心放回底栏右侧；低频能力从一级拿掉。

**同城活动**

- 活动行一类：发现 / 活动列表 / 发布 / 我的。列表是**分类 + 时间/地点卡**，不是线路海报。
- 豆瓣同城 / Meetup：日期块（月/日/周）在左，标题和地点在右。

**户外社区**

- 「活动」默认等于报名中的出行。若产品同时做山野和同城，必须在**文案和卡片结构**上拆开，不能共用一张风景卡。

## 3. 信息架构（已采用）

```
底栏（4 项）     首页 ── 山野拼团（发现、筛选、发团）
                 活动 ── 同城局（掼蛋 / 跑步 / 电影 / 招募）
                 行程 ── 待出行 + 历史报名（登录后）
                 我的 ── 会员、认证、客服与规则
二级页           官方 ── 加微信、关注、FAQ、规则（从「我的」或首页页脚进入）
```

底栏固定在窗口底部，中间内容区单独滚动（H5 的 `.mp-phone` 做成上导航 + 中滚动 + 下 Tab，避免长页要把底栏卷走）。

活动 Tab **不改名**。页面主标题改成「同城局」，并写清「户外线路请走首页」，避免和俱乐部黑话打架。

## 4. 活动页结构

1. 顶卡：本周几场 + 一句话定位 + **发起一局**
2. 四宫格分类：掼蛋 / 跑步 / 电影 / 招募（带短提示）
3. 列表：左侧日期块（日 + 周几），右侧标题、地点、余位、发起人；有封面则右侧小图
4. 空态：四个分类仍可点，引导去发布页

不再使用首页那种 140px 风景大图。价格在同城局里弱化（免费局只标免费）。

## 5. 官方页结构

1. 图形标 + 主按钮：**复制官方微信**、**复制用户群名**
2. 快捷入口：意见反馈、抽奖、学生认证（H5）、平台规则（锚点）
3. 关注我们：公众号 / 视频号 / 小红书等，点卡片复制
4. 常见问题：手风琴，默认展开第一条
5. 平台规则：默认收起；`#rules` 进入时自动展开并滚到规则

## 6. 不在本期做

- 自定义 tabBar 中间「+」发团（微信原生 tab 够用，H5 首页已有发团）
- 真机微信客服会话（演示环境无 AppId 客服）
- 活动页独立搜索 / 城市筛选（数据量还小）
- 小程序独立学生认证页（H5 已有 `/m/student`；小程序首页按钮暂跳「我的」）

## 7. 同城局轻报名（已落地）

对照微信《小程序设计指南》（一页一个重点、减少输入、列表分组）以及携程行程、Meetup / 活动行的局详情。

| 页面 | 专业做法 | 落地 |
| --- | --- | --- |
| 首页 | 首屏是即将出行 + 可报的团，筛选默认收起 | 日期日历整块折叠；会员/学生/抽奖等增长入口挪到「我的」；页脚只留客服 |
| 我的 | WeUI 分组列表，不重复「行程」Tab | 出行 / 权益 / 服务三组 cell；去掉即将出行大卡 |
| 局详情 | 周几、几点、在哪、还缺几人、名单 | 隐藏座位图、装备、保险入口、推荐佣金、本团画像；名单不展示年龄段 |
| 局报名 | 姓名 + 手机 | 后端 `channel=activity` 跳过身份证、紧急联系人、弃权；按 `user_id` 去重 |
| 已报名 | 不要再推报名 | 有 `myEnrollment` 时隐藏报名按钮，改为「已报名，到场找发起人即可」 |
| 行程 | 下一趟 + 轻操作 | 待出行/历史 chips；取消改成文字链；免费局不显示 ¥0 |

山野团报名规则不变。同城局满员候补文案为「本局已满」，成功为「已报名，到场即可」。

实现要点：

- 后端 `server/src/services/enroll.js` 按 `sch.channel === "activity"` 分支
- 列表 `GET /schedules?channel=activity|trip`
- H5 `web/src/utils/activityKind.js`、`trips.js`；小程序 `utils/activity-kind.js`
- 种子 A01–A04 在 `server/src/seed/run.js`
